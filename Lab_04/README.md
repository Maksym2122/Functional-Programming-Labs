## Теоретичні нотатки

### Ліміт рекурсії в CPython
Інтерпретатор CPython обмежує максимальну глибину стека викликів (за замовчуванням `1000` кадрів, перевіряється через `sys.getrecursionlimit()`). Це захищає програму від переповнення системного стека мови C (`Segmentation Fault`). При перевищенні ліміту генерується виняток `RecursionError`.

### Чому в Python немає TCO (Tail-Call Optimization)
Гвідо ван Россум свідомо відмовився від впровадження оптимізації хвостової рекурсії (TCO) в CPython з кількох причин:
1. **Збереження повних стектрейсів (Tracebacks):** заміна виклику на цикл знищує проміжні кадри стека, що ускладнює налагодження помилок.
2. **Динамічна природа мови:** функція у Python може бути перевизначена під час виконання (monkey-patching), тому компілятор не може безпечно гарантувати, що рекурсивний виклик посилається на ту саму функцію.
3. **Pythonic-підхід:** для задач із великою глибиною вкладеності замість глибокої рекурсії рекомендується використовувати ітеративні цикли або генератори.

### Коли ітеративна альтернатива безпечніша
Ітеративні алгоритми (`fib_iter`, `bfs_level_order`, `dfs_preorder_iter`, `lcs_iter`) використовують пам'ять купи (heap) замість обмеженого стека викликів. Вони є обов'язковими при роботі з великими вхідними даними (наприклад, дерева висотою понад 1000 рівнів або рядки довжиною у тисячі символів).
