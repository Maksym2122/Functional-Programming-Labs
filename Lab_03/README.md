# Лабораторна робота №3. Незмінні структури даних (Immutability) у Python

**Варіант 12:** Ресторанне меню (`Dish`, `Ingredient`, `allergens`, `meta`).

## Реалізація
- `Ingredient` реалізовано як `NamedTuple` (повністю хешована структура з нульовим оверхедом).
- `Dish` реалізовано як `@dataclass(frozen=True, slots=True)`.
- Колекція інгредієнтів зберігається у `tuple[Ingredient, ...]`, алергени — у `frozenset[str]`.
- Метадані (`meta`) обгорнуті у `MappingProxyType` із попереднім копіюванням вхідного словника.
- Усі зміни стану (`add_ingredient`, `add_allergen`, `update_price`, `apply_discount`) реалізовані як чисті функції, що повертають нові копії об'єктів.

## Примітка щодо хешованості
Сутність `Ingredient` є повністю хешованою та може використовуватися як ключ у `dict` чи елемент у `set` (а також як аргумент для `@lru_cache`). Сутність `Dish` не є хешованою через наявність поля `meta: MappingProxyType`, оскільки вбудований `mappingproxy` у Python не підтримує `hash()`.

## Висновки щодо продуктивності та переваг
1. **Переваги:** повна відсутність побічних ефектів (side effects), безпечне передавання об'єктів між функціями без захисного копіювання (`deepcopy`), легке кешування обчислень (`lru_cache`) та детерміновані тести.
2. **Накладні витрати та швидкість:** створення нових кортежів при кожному оновленні потребує алокації пам'яті під новий `tuple`, проте за рахунок відмови від `copy.deepcopy` (який необхідний у мутабельному коді для захисту стану) іммутабельні оновлення через `dataclasses.replace` працюють у кілька разів швидше на колекціях середнього та великого розміру.
